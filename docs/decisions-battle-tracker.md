# 決策記錄：跑團對戰記錄工具與角色卡翻新

> 開始：2026-11-24。方式：以「細問」強度逐輪討論。每定一條追加「結論＋理由」，另列待定問題。

## 已確定

### D1 保留決策記錄
- 結論：留。
- 理由：討論跨多輪，接續時不必重問。

### D2 新工具與現有 1v1 對戰的關係
- 結論：先把「DM 單人用的戰場記錄工具」做成一個**新的工具**，只滿足朋友目前的需求。**現有 1v1 對戰的程式碼不刪**。之後再看需求決定要不要做「分層」（共用的記錄核心＋可選輔助），做到什麼程度。
- 理由：先交出朋友要的東西；不為了還沒確定的大架構重寫 engine.js。

### D3 使用者與操作方式（第一階段）
- 結論：第一階段**只有 DM 一個人用**，玩家不碰工具。
- 理由：朋友說「DM 私底下記錄」；單機即可，不需要伺服器。
- 備註：擲骰「工具擲」與「DM 輸入 Discord 擲出的成功數」兩種都留，是依建議的暫定值，未被反駁。

### D4 DM 最痛的點與優先順序
- 結論：核心先做 ① 記 HP／狀態／能力升降、② 先攻順序與行動數、③ 擲命中／傷害／相剋。④ 查招式與特性效果、⑤ 多隻野生與多方、⑥ 場地天氣事件也需要實現。
- 理由：使用者明確指定。

### D5 暈厥規則
- 結論：倒下的寶可夢留在場上，不能行動也不能反應，回合被跳過；倒下方的訓練家在**戰鬥輪結束時**收回並換新的，新的寶可夢**下一輪**正常行動（下一輪開始擲先攻）。擊倒方可以繼續行動，**隨時可以選擇保留，保留後戰鬥輪結束**。
- 理由：原書訓練家的額外回合在戰鬥輪即將結束前，戰鬥輪結束是安全替換的時間點；書上的結束條件是「沒有人可以或想要再行動」。
- 適用：要修改現有 1v1 引擎（`battle/js/engine.js` 的 checkFaint、faintSwap 流程）。

### D6 工作態度
- 結論：不必太在意 token，自然進行。
- 理由：使用者說之前是太焦慮。

### D7 開發順序
- 結論：**今天只做 DM 單人的 L0 記錄工具**，用現有程式碼以外的新檔案。**今天不碰其他舊程式碼**（含 1v1 引擎、`battle/js/engine.js`）。做法是「A 的做法、B 的精神」：先交出單機工具給朋友，但**資料格式一開始就按日後會被多人／平台讀取來設計**，不依賴單機假設。
- 理由：想先做出能方便記錄資訊、馬上給朋友用的東西。
- 影響：D5 的暈厥修正（改 1v1 引擎）與特性／招式特效（乙）**不在今天範圍**，延後。

### D8 兩個工具，不做等級開關
- 結論：不做 L0～L3 的可調等級。分成**兩個獨立工具**：**L0＝記錄／表格工具**（今天做，給朋友用）；**L3＝全自動跑團平台**（長期目標）。
- 理由：等級開關太複雜。
- 備註：L0 要多簡、能不能有少量輔助，見待定。

### D9 角色卡：檔案制，玩家自己管
- 結論：角色卡是玩家自己的 **JSON 檔**，不用帳號。玩家在平台開啟本地角卡，平台把它顯示成資訊更完整的角色檔案，並自動算好命中骰、傷害骰等（JSON 只記配招等原始資料）。**玩家在平台上編輯自己的角卡**，跑完團時**匯出存檔**。**GM 不修改玩家的資料。**
- 理由：簡單、可離線、不必維護帳號系統；資料所有權在玩家。
- 影響：不需要「寫回要不要同意」的機制。跑團中玩家寶可夢的即時 HP 與狀態，L0 由 DM 記錄；平台版（L3）才讓玩家自己動自己的卡。

### D10 GM 備團先做的項目
- 結論：先做 ① 野生寶可夢遭遇、② NPC 訓練家與隊伍、⑤ 遭遇表／戰鬥模板（備好後一鍵開戰）。地圖場地、事件觸發、道具獎勵之後再看。
- 理由：與戰場記錄直接相關，可重用規則站的隨機產生器。

### D11 暫定值（使用者同意）
- T1：對手場上沒人時，擊倒方只能用以自己或場地為目標的招式。（實際實作屬於 1v1 引擎，延後。）

## 2026-11-25 網友意見的整理（提案，待使用者確認）

來源：使用者提供的兩份 Discord 對話（對話1、對話2）。使用者是「藻蛙」。

**四個不同的需求被混在一起：**
1. **GM 記數板**（桁煠、博愛座、艾利）：記場地、天氣、狀態、血量、各種「幾輪後到期」的計數；不要自動判定，「夠用就好、其餘 ST 自己處理」。
2. **玩家唯讀看板**（博愛座）：玩家只要能看到剩餘輪數、先攻、血量，不必操作；擲骰與扮演留在 Discord。藻蛙自己也提過「GM 開直播就好」。
3. **玩家自助擲骰與自動判定**（藻蛙本人的偏好、Da Capo「全都要、想的是平台」）：少數意見，工程量最大。Da Capo 也提到可以做 Discord Bot 或擴充 HKTRPG。
4. **玩家對玩家的對戰**：博愛座指出已有 1v1 對戰網頁，不必重做。

**原書本身就有規格：** 戰鬥組織表（規則站「說書人指南 → 組織戰鬥流程」與「結語 → 戰鬥組織表」）分兩塊：戰場（位置、天氣、場地、其他，各有剩餘戰鬥輪；雙方各自的防護力場、入場危害、掩護、目標數）與戰鬥輪（輪數、先攻順序、參戰者、持有物、異常狀態、行動計數、戰鬥輪結束時的效果）。書上建議由一個人負責記錄。

**提案：**
- L0＝戰鬥組織表的電子版，核心功能是「條目計數＋一鍵下一輪」（所有倒數條目 −1、到期提示、行動計數歸零、列出戰鬥輪結束時要處理的效果）。不做自動判定。
- 先制／反應：每人每輪填一個數字，自動排序（桁煠、小閔的需求，不用自動計算）。
- 玩家唯讀看板：L0 先用「複製成 Discord 文字」與開直播；唯讀連結之後再做。
- 玩家自助擲骰：做成「角色卡檢視器」（本機開 JSON，顯示命中骰、傷害骰，按鈕擲骰，結果可複製到 Discord），不需要房間與帳號。對應 D9。
- 完整的房間式跑團平台（L3）：先不做，等前面幾項有人用、有真實需求再決定。

### D13 L0 功能清單（使用者指定）
- GM 專用畫面；記錄戰場（場地、天氣、入場危害等）；追蹤血量、意志、能力升降、異常、多重行動次數。
- 兩個大按鈕：「下一回合」、「下一輪」；顯示本輪所有參戰者的行動順序。
- 自由新增參戰者（寶可夢與訓練家），陣營標籤（玩家 A／B／C／D、敵方、NPC），GM 可編輯陣營與參戰者資訊。
- 參戰者是寶可夢時可展開招式，自動算命中與傷害骰池，並記住每輪一次的動作（例如反應）有沒有用過。
- 匯出／匯入：今天跑完存檔，下次匯入繼續。
- 備註：Q17（規則站招式表按先制排序）以後再做。

### D14 資料格式要先規劃
- 結論：匯出匯入的格式與第三段角色卡共用「角色」格式，所以先寫格式草稿（`tracker/docs/data-format.md`）再開工。

### D15 回合與輪的語意（使用者確認）
- 結論：先攻順序上每位有 ✓／✗ 標記，代表「這回合有沒有行動」。**下一回合**：目前輪到的人若標 ✓，行動計數 +1；然後把「目前輪到」移到下一位（跳過倒下的）。**下一輪**：列出「戰鬥輪結束時要處理的效果」，並有一個選項決定要不要自動扣 HP（預設不扣，只提醒）。
- 理由：照使用者的描述。實作補充：所有人都保留（或行動用完）時，「下一輪」按鈕會提示。

### D16 先攻由 GM 輸入
- 結論：先攻在 Discord 擲，GM 手動填進工具。工具不擲先攻。

### D17 角色格式統一
